# 屏幕共享复用 IM RTC

> 文档类型：开发过程或验收记录。保留当时的设计、环境和执行边界；当前能力以[功能状态](feature-status.md)为准，不作为当前启动或升级指南。

> 本文保留首次SCREEN_SHARE来源方案和当时验收历史。当前开发改为用户明确选择的第二Camera视频轨道，保留业务screen来源与发布名，见[第二视频轨道设计](im-rtc-second-video.md)。平台底层来源与业务来源不同，不能将旧403当作新方案失败。

## 问题与方案

旧客户端为屏幕另建 P2P 连接，依赖业务侧 SDP/ICE 信令和独立 STUN/TURN。摄像头和麦克风已经通过 IM RTC，屏幕应复用相同授权频道，作为独立视频轨道发布，保持摄像头同时可用。

已安装 `@deeprespond/im-web@1.0.0-alpha` 的 LiveKit provider 支持扩展发布。沿用 `frontend/patches/` 的 pnpm 补丁机制，应用只使用 SDK 公开接口，不持有 LiveKit Room、媒体凭据或自行建立 PeerConnection。

## SDK 契约

- `ChannelHandle.publishScreenTrack(track, {name})`：仅 video publisher 可调用；输入为用户主动选择后取得的实时视频轨道。来源标记为 `screen`，发布名使用 `screen:<业务共享 sessionId>`。
- `ChannelHandle.stopScreenShare()`：仅清理屏幕轨道，不能影响摄像头、麦克风；离会和晚到发布同样收尾。
- `ChannelTrack` 增加可选 `source`（camera/microphone/screen）与 `publicationName`。频道继续执行 HTTP 成员与媒体身份授权校验，然后透传来源信息。
- 本次扩展限定桌面使用的 ES module 发行物。不支持这些接口的媒体适配器明确返回 unsupported，不静默回退 P2P。

## 业务流程

用户点击 → 立即申请系统选屏 → 请求业务共享所有权 → 校验最新所有权 → SDK 发布独立屏幕视频 → 其他成员按授权用户名、来源和共享 sessionId 显示轨道。

接收轨道可能先于业务快照到达，先缓存再按快照匹配。接管后停止旧本地采集和发布，旧发布名不能覆盖新共享。取消选屏、发布失败、所有权丢失、离会均停止采集；发布失败回滚自己取得的共享所有权。RTC 重连与授权续期由 SDK 管理，接收超时给出重试入口。

旧后端共享配置/信令接口保留兼容旧客户端，新客户端不再调用。公网连通性依赖 IM RTC 的实际部署；本机系统选屏权限仍须单独验证。接收人数没有 SDK 可靠回执时不再展示推测人数。

## 验证与边界

执行 SDK 与业务生命周期契约、类型检查、生产构建。页面执行桌面和窄窗口完整流程，先单独冒烟确定性失败夹具，全部断言通过后截图，逐张实际查看。结果、日志、失败和自动生成报告保存在 `.artifacts/IM视频通道屏幕共享/`，30 分钟 E2E 调试预算到期停止并降级 API 验证。夹具、真实 IM RTC 传输、原生系统选屏分别记录，不互相替代。

官方参考：[LiveKit 屏幕视频轨道](https://docs.livekit.io/transport/media/screenshare/)、[IM 频道授权接口](https://www.syznlink.com/docs/client/web/channels)。

## 平台集成发现

2026-10-24 使用临时用户和独立频道连接现有 IM 测试平台：两端 SDK 入会成功，发布 `ScreenShare` 来源时 LiveKit 返回 `insufficient permissions to publish`，发布失败后客户端停止采集并回滚所有权。官方频道创建/修改接口没有来源权限参数。未改平台配置、未伪装摄像头来源，也未将失败标为通过。

若继续使用原生SCREEN_SHARE方案，平台须在video publisher首次加入、恢复、续期和权限同步中允许该来源；subscriber不得发布，audio频道保持麦克风限制。但公开IM频道契约没有来源授权参数，不能要求调用方传canPublishSources；当前按用户选择改用第二普通视频轨道，独立验证兼容性。本次不采集系统声音、不修改平台权限。

为了继续验证客户端，提供显式 `--local-rtc` 分支：真实 SDK LiveKit provider + 独立本地 LiveKit 服务，替换 IM 频道控制面、业务 IPC 与合成采集。这个分支可以证明真实媒体经 SFU 发布/接收和 UI 生命周期，不能证明已部署平台已授权或真实 Tauri 系统选屏通过。所有线上失败与本地结果分别记录。
