# 同账号跨端入会失败页修复

> 文档类型：开发过程或验收记录。保留当时的设计、环境和执行边界；当前能力以[功能状态](feature-status.md)为准，不作为当前启动或升级指南。

基线：develop 621fea8，沿用 investigate/same-account-meeting-entry worktree。已用真实 IM/RTC 与当前 Tauri 复现 HTTP 409 / conflict / joined_on_other_device。

## 实现范围

1. 保留 SDK 的跨端占用原因，显示中英文明确提示：账号已在另一设备参会，先在另一设备退出，再重试；退出占用可能仍在释放。
2. 失败页提供“取消入会，返回首页”。同步标记本端会话结束，再释放本端 RTC、聊天订阅和业务 WebSocket，关闭持久会议 UI、清除入会意图。不得调用普通成员 leave、结束会议、移除成员、退出 IM 登录或撤销其他设备权限。房主及普通成员均遵守该规则。
3. 保留重试：另一设备自行退出后可重试；仍占用时继续展示明确提示。
4. 关于主动断开另一设备的交互方式，已向用户询问偏好；完成前不使用 IM 设备踢出登录冒充会议退出。

## 验证与提交

- 先补充既有 RTC 错误分类和真实 RoomProvider 页面回归：跨端占用、取消后无 leave/end 请求、普通成员取消同样安全、取消后再次入会以及迟到 SDK 初始化不能重启会话。
- 单独冒烟确定性故障入口后执行完整页面验证；检查类型及相关会议回归。原生调试使用已验证的隔离构建，先探测现有服务及测试登录态。真实 RTC 验证“第一设备连接 → 桌面收到跨端占用 → 取消返回首页 → 第一设备仍连接/房间仍活动”；失败路径与释放后重试保留真实结果。
