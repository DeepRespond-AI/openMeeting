## 阶段与提交

0. 先提交本计划，再提交既有私有群聊天及文件迁移，包括入会授权与撤销、SDK 适配器及回归测试。
1. 会议通知：使用持久化业务发件箱和稳定去重 ID，通过 user_ms 及 IM 服务端 SDK 投递。覆盖预定创建、变更、取消、提醒，
   以及录音处理完成与失败。IM 工作台渲染类型明确的会议卡片，消息中不得暴露会议密码。
   IM 不提供 Windows/Web 离线系统推送；提醒依赖后端调度器，重连后显示。
2. 未读与已读同步：使用 IM 会话未读状态并订阅变化，仅在文档获得焦点、聊天可见且滚动到底部时标记已读。
   查看历史时保留未读，不实现本地序号差值计数器。
3. 资料及文件：通过 IM 缓存和批量查询获取成员资料；使用 SDK 群文件分页列表、下载能力，覆盖空态、错误、加载和重试。
   房间角色沿用业务状态，不假定 IM 头像 URL 一定是可公开访问的 HTTP URL。
4. 富消息及操作：复用工作台消息渲染和 SDK 操作，支持回复、表情回应、撤回本人消息、权限允许时的置顶与已读回执，
   以及失败消息的重发或丢弃。明确展示被拒绝的操作，并保留群文件 ACL。
5. 局部状态通知：对房间设置及主持人变化发送持久化 IM 状态失效提示，校验发送方和载荷后重新获取权威快照。
   业务 WebSocket 继续负责入会、移除、租约及强恢复，不将任意用户自定义消息当作权限或媒体控制命令。
6. 验证、生成带截图的报告、更新文档并完成最终提交。

每个阶段单独提交并完成相关检查。如果 SDK 证据要求收窄能力，应更新本文并记录原因，不另行实现一套本地 IM。
会议主持人并非 IM 群主，因此主持人专属的群特权操作必须经过业务服务授权。

## SDK 能力缺口

屏幕共享（含音频及采集生命周期）、强制远端媒体控制、逐轨道网络和质量统计属于 IM/RTC SDK 能力增强需求，
在公开 SDK API 支持之前保留既有实现。频道每日用量不能作为实时媒体统计。录音、STT 和总结仍属于业务服务。
公开聊天室不具备本功能要求的私有成员关系及持久化历史契约。群文件文档规定上限为 1000 个；
保留策略取决于 IM 配置，解散群会删除群文件，因此会议结束时应禁用群，而非解散群。

使用项目已有的 Python、TypeScript、SDK 契约及 Playwright 工具。浏览器运行前先单独冒烟确定性夹具。
失败路径必须有明确控制入口，覆盖会话拒绝或不可用、历史/发送/文件错误、慢上传与加载、文件空态及消息操作被拒绝。
验证重试行为，确认没有本地回退实现。

先探测既有原生 CDP 客户端。制定计划时，端口 9256/9257 未开放，业务 Docker 服务及 Next 3118 正在运行，需予以保留。
使用独立端口及构建目录运行修改后的浏览器开发版。在不影响用户会话的前提下，尝试专用原生和真实 IM 验证。
夹具结果不得标记为原生或真实 IM 验收通过。

E2E 调试开始时设置 30 分钟预算，超时后保留失败并降级为 API 验证，明确说明限制。先完成断言，再进入截图阶段。
按适用范围采集桌面和窄视口的正常、加载、成功、空态、失败、权限、长内容，以及抽屉和弹窗打开、滚动、关闭画面。
使用图片查看器逐张检查，并单独保存明确的视觉检查记录；未查看的图片不得标记为视觉通过。

按仓库规则，本轮产物放入 `.artifacts/meeting-im-integration/`，不使用 `Agent测试/`；脚本放入 `tests/e2e/`。
每一步输出操作、预期、实际、是否通过及截图路径等结构化数据。根据步骤结果、视觉检查、环境和清理记录生成 `测试报告.md`，

## 实现说明

阶段 1 还在会议信息中增加 IM 直接邀请卡片。既有模型没有受邀人列表，因此预定事件通知发送给所属用户。
处理结果通知与任务终态一同提交。投递给 IM 的去重 ID 使用稳定 UUID，原始业务 ID 在真实平台测试中被拒绝。
群回执受 IM 配置控制，关闭回执不能影响普通文字消息发送。

已交付的富消息子集及 SDK、配置缺口见[能力说明](meeting-im-capabilities.md)，包括特权置顶和会中语音录制。
收到的语音消息复用现有渲染器。
