# 同账号跨端入会卡住排查

> 文档类型：开发过程或验收记录。保留当时的设计、环境和执行边界；当前能力以[功能状态](feature-status.md)为准，不作为当前启动或升级指南。

基线：develop 621fea8（2026-10-30 拉取远端，无新增提交；保留主工作区已有修改）。

用户触发条件：移动端已进入自己创建的会议，桌面端使用同一账号加入相同会议号。目标是复现并解释加载、连接失败、房主退出被拒三个状态。本轮先排查，不改变同账号多端参会策略。

## 步骤

1. 阅读当前项目启动、原生测试及会议代码，探测并保留已有服务和登录态。
2. 复用日常业务网关 39110，使用隔离测试 profile 和当前 develop 前端。优先复用已有原生调试壳，明确其版本边界；不得操作用户正在运行的桌面进程或移动端应用。
3. 先单独冒烟身份认证、业务建房、IM 聊天和 RTC 授权。随后用真实 SDK、两个独立设备身份、同一业务账号验证重复入会，对照不同账号入会。若不能实际执行 Android，则明确跨设备桌面验证不等于 Android 原生验收。
4. 累计原生/E2E 调试预算 30 分钟。逐步输出操作、预期、实际、通过状态和截图路径，失败保留证据。验证后统一采集桌面与窄视口相关加载、成功、错误状态并实际查看。
5. 报告从结构化产物生成，产物位于 `.artifacts/same-account-meeting-entry/`，报告归档至 `docs/testing/archive/同账号跨端入会排查/`。仅关闭本轮启动的进程、结束本轮测试房间、恢复测试 profile。

## 待验证的假设

- 业务成员唯一键为 room_id + user_id，重复加入幂等返回同一参与者及房主角色。
- RTC 的设备会话与业务成员身份不一致，可能在同账号第二端加入时冲突；需真实 SDK 错误确认，不凭截图判断 IM 服务故障。
- RoomProvider 等待 RTC、设备和聊天就绪，45 秒后进入通用失败页。
- 失败页调用普通 leave 接口，该接口拒绝房主，因此无法从该按钮退出。

按阶段提交排查文档、可复用验证脚本、最终证据报告。若发现需修改产品策略的问题，在报告中分别列出业务端、客户端与 SDK 的责任边界。
