# 移动端应用更新

Android 客户端会在启动、回到前台和运行期间定期请求后端检查更新；用户也可以在「设置 → 关于」中手动检查。普通更新会提示用户安装；命中强制发布或最低支持版本策略时，会要求先升级（录音进行中除外）。

- `direct` 渠道：客户端从业务后端下载 APK、校验 SHA-256，再调用 Android 安装器。用户需要允许应用安装未知来源应用。
- 商店渠道和 iOS：客户端打开管理端配置的商店链接。
- 发布时，在管理端「版本发布」选择 Android 平台并创建版本，上传对应渠道的 release APK 后发布。版本名和构建号来自 `mobile/pubspec.yaml` 的 `version`。
- 同一更新渠道的所有 APK 必须使用同一个 Android 签名密钥，否则系统不允许覆盖安装。debug 签名安装的版本也不能直接由 release 签名覆盖，需要先卸载。

各构建环境、密钥和命令见 [README 的构建章节](README.md#构建) 与 [Android 签名密钥说明](android/keystores/README.md)。
