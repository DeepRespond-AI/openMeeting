# 会议连接、异常处理与恢复

本文维护当前会议连接、重试及清退规则。公共字段以 [API 契约](../server/API.md)为准，完成状态与未验收项见[功能状态](feature-status.md)；具体 SDK 兼容扩展见[补丁说明](../frontend/patches/README.md)。

## 1. SDK 与责任边界

项目直接使用 DeepRespond SDK：

| 层 | 当前接入 | 负责内容 |
|---|---|---|
| 桌面 IM | `@deeprespond/im-tauri@1.0.0-alpha`、同版 `im-web`，Rust 插件 | 引擎鉴权、IM 连接、消息同步、桌面能力 |
| 桌面音视频 | `im.channels` / `ChannelHandle` | 频道加入、原会话恢复、媒体连接、授权音轨、频道心跳、媒体凭据续期 |
| 服务端平台接入 | `deeprespond-im-server-sdk` / `AsyncDRClient`，集中在 `user_ms` | 创建频道、签发票据、撤销票据、移出成员、关闭频道、App Token 管理 |
| 业务会议 | `meeting_ms` + 自有 REST/WS | 成员席位、等候室、主持人权限、会议结束、录制和会后任务 |
| 屏幕共享 | IM RTC 中的独立视频轨道 + 业务共享归属 | 单发布者仲裁、采集与发布清理；传输规则见[共享设计](im-rtc-second-video.md) |

业务通过 IM SDK 接入媒体，底层兼容扩展集中在 SDK 补丁，不据此假设业务拥有平台录制或媒体管理 API。

SDK 接口按锁定依赖和本地类型核对；参考资料：

- [Tauri SDK 概述](https://www.syznlink.com/docs/client/tauri/overview)
- [Tauri 独立 RTC 频道](https://www.syznlink.com/docs/client/tauri/channels)
- [Web 频道接口与恢复](https://www.syznlink.com/docs/client/web/channels)
- [Python SDK](https://www.syznlink.com/docs/server-sdk/python/)

已确认的公开接口：`getCurrentSession()`、`resume({channel_id, session_id, signal})`、`join()`、`getSnapshot()`、`subscribe()`、`refresh()`、`leave()`；事件包括 `connectionChanged`、`sessionLeft`、`channelClosed` 和授权音轨事件。

SDK 已负责频道心跳和授权续发，业务不再建立第二套媒体心跳或在每次 `reconnecting` 时重新 join。`resume` 仅可恢复当前登录的有效会话，默认不开启采集；恢复后让用户确认开启麦克风/摄像头。终态、封禁、忙线和权限拒绝不自动反复签票。

## 2. 目标、范围与约束

异常处理目标：服务端业务状态正确、已确认数据可恢复、有限重试、权限失效及时生效、用户能判断当前结果、日志可以定位一次操作。

当前实现包含业务错误分类、独立连接租约、心跳检测、成员清退、主持人失联收尾、结束幂等和广播发送超时。meeting_ms 按单实例部署。

录制持久补传、平台补偿、多实例广播及故障演练未作为当前可靠性保证，限制见[功能状态](feature-status.md)。

不使用客户端本地业务数据库。客户端临时录制缓存仅允许私有临时文件队列，服务端仍是业务数据来源。不能恢复任何节点都未采集到的音频。

## 3. 错误契约与重试

服务端保持 `{detail, code}`，保留现有 `not_found/ended/wrong_pwd/full` 入会码。补充 `forbidden`、`not_joined`、`waiting`、`host_required`、`muted_by_host`、`conflict`、`invalid_input`、`recording_conflict`。HTTP 状态描述类别，`code` 描述业务原因；前端不得将所有 403/409 转成密码错误/满员。

| 错误 | 自动处理 | 用户结果 |
|---|---|---|
| 401 / 登录切换 | 停止旧连接、清理媒体，沿用登录失效处理 | 重新登录 |
| 403 / 权限、等候、静音 | 不自动重试、不新建媒体会话 | 展示原始业务提示 |
| 404 / 已结束或已移出 | 终止重连、更新房间状态 | 离开房间或查看已生成记录 |
| 409 / 并发冲突 | 拉取最新状态；仅既定幂等操作可重放 | 提示状态变化 |
| 422 / 参数无效 | 不重试 | 保留输入，提示修正 |
| 网络、429、502/503/504 | 只对安全读取或有稳定幂等键的写入有限重试 | 等待、重试、取消 |
| 请求超时，结果未知 | 先查询结果；禁止盲目重放非幂等写入 | 明确“结果确认中” |

DeepRespond 的 App Token 刷新、冷却和内部重试由 Python SDK 负责；业务层不套无限重试。平台清理尚无完整的持久补偿任务保证；当前可用的本人会话显式恢复见[当前功能与限制](feature-status.md)。凭据错误、应用停用等应告警，不能通过不断生成新客户端绕过 SDK 冷却。

## 4. 连接和成员生命周期

### 4.1 分开看待四条链路

业务 WS、IM 引擎、RTC 音视频、录制上传分别维护状态。WS 短暂断开不立即断开仍有效的 RTC，也不立即把主持人转走；恢复时获取最新 `room_state`，补拉聊天。屏幕共享沿用现有独立会话清理。

### 4.2 业务 WS 活性

客户端发送应用层 `{type:"ping"}`，服务端返回 `{type:"pong",ts,data:{}}`。这不是频道媒体心跳。默认 15 秒一次；服务端 45 秒未收到客户端消息关闭失活 socket；Rust 同时检测服务端消息，防止“TCP 看似在线但业务已失联”。正常业务消息也能续活。

在线租约按每条 WS 连接持久化，包含随机连接 ID、房间、成员及 `last_seen_at`；同一成员多连接独立续租。关闭旧连接只删除自己的租约，不得将新连接误标离线。广播要限制发送时间，不让一个慢接收者阻塞整个会议。

### 4.3 离线宽限和主持人策略

主持人策略为“主持人超时后结束会议并保留录音处理”，不自动向普通成员授予主持人权限。自动接管需要联席主持人/候选人规则及录制交接协议后再启用。

默认值（可配置，非平台保证）：最后一条有效 WS 确认断开后，使用独立的 3 秒重连窗口；每秒扫描一次。`RoomParticipant.disconnected_at` 持久化断连时间，避免服务重启丢失期限；`touch` 或幂等重新入会清除期限，同账号尚有有效连接时不设置期限。只有实际删除了自身租约的断开清理才能设置期限，旧连接重复清理不能重新启动已取消的期限。

未建立 WS、未观察到明确断连或等待席位保留原有策略：成员活性宽限 90 秒、主持人 180 秒、静默 WS 心跳超时 45 秒。异常退出通常会由操作系统释放 socket；完全断网或休眠未及时释放 TCP 时仍依赖心跳，不能承诺瞬时检测。计时从确认断开开始；外部平台撤权失败保留事务和断连期限，后续扫描重试，不把撤权失败写成成功。短暂网络中断超过新窗口也会被清退，主持人会结束会议；可用 `OPENMEETING_ROOM_DISCONNECT_GRACE_SECONDS` 调整该取舍。

| 场景 | 行为 |
|---|---|
| 最后一条 WS 确认断开 | 保留席位 3 秒供原身份重连；到期后按当前角色清退或结束 |
| 同账号另一条 WS 仍活跃 | 保留席位，不受旧连接断开影响 |
| 普通成员超时 | 房间行锁内复查租约，移除席位/共享标记；撤销媒体授权并移出平台会话 |
| 主持人超时 | 房间行锁内复查当前主持人和租约；结束会议、创建唯一纪要记录及录制任务、通知存活连接、关闭频道 |
| 主持人权限已手动转移 | 以扫描时锁定的当前主持人为准，旧主持人按普通成员处理 |
| 服务重启 | 租约在数据库中保留；允许重连宽限后清理，不靠进程内计时器判断永久在线 |

重连注册、租约续期和超时清退使用一致的房间锁顺序；过期任务不得删除新连接。扫描失败记录日志，下一轮重试；停机先停止扫描，再关闭数据库。

## 5. 结束会议和并发

结束会议在同一事务内完成 `LiveRoom.ended`、`Meeting`、预定关联及录制 `Job`。同一主持人重试已完成的结束请求，返回原 `meetingId/jobId`；不得重复创建记录，也不能向其他成员泄露主持人纪要。

房间结束与音频提交使用同一房间行锁，已确认分段必须在结束事务可见。结束后新分段仍拒绝；当前不承诺跨结束补传，不能通过取消权限检查绕过结束边界。

WS 广播失败不回滚已提交结果；SDK 频道关闭失败不把已结束会议改回 active。平台关闭按现有尽力处理方式执行，尚无完整持久化补偿保证。自动结束与手动结束复用同一收尾函数。

## 6. 可观测性、权限与降级

- 日志关联 `room_id/participant_id/job_id/operation_id`、错误码、重试次数和耗时；禁止记录票据、Token、密码、音频正文或 SDK 原始错误载荷。
- 监控重连次数、失活连接、席位清退、主持人超时结束、上传积压、录制缺段、任务排队时长、STT/LLM 失败率、平台清理失败。
- RTC 不可用时保留可用的文字/会议控制；STT/LLM 不可用时保留录音并提示可重试。
- 加密提示仅表达已核实的传输保护；未经验证的应用级端到端加密不能显示为已启用。
- 多实例前必须补充分布式广播、共享回调去重、任务租约及共享文件访问，不能仅增加进程数。
